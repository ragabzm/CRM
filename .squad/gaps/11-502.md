# Gaps found while building story 11 / 502

Things that were broken, missing, or inconsistent and are **not** described in
`11-story-502.md`.

## `composer openapi:generate` pointed at the wrong command

`backend/composer.json` mapped `openapi:generate` to
`@php artisan scramble:export --path=openapi.yaml`, but this repository has its
own `openapi:generate` artisan command, and only that one is correct:

- Scramble's exporter writes **JSON** whatever extension you hand it, while the
  published contract is YAML — so the composer script could never have produced
  the committed document.
- `OpenApiGenerateCommand` swaps in a throwaway in-memory SQLite schema for the
  duration of generation. `scramble:export` does not, so it tries to reach the
  real database and dies with
  `could not translate host name "postgres"` on any machine that is not inside
  the Docker network — which is every developer machine.

`openapi:check` always called the artisan command, so drift detection worked
while the remediation it prints (`run composer openapi:generate`) crashed. That
is the worst arrangement: CI tells you the document is stale and the fix it
names does not run.

**Fixed here.** `composer.json:76` now reads `@php artisan openapi:generate`.
Verified: `composer openapi:generate` writes the YAML, and `openapi:check`
reports it up to date.

Worth noting for whoever regenerates next: this had been broken since the
contract was introduced, and nobody hit it because `openapi.yaml` is only
regenerated when routes change.
