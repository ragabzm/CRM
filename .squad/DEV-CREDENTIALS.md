## الحسابات دي بقت في الـ seeder

كانت اتعملت **يدوياً** قبل كده، فـ `migrate:fresh --seed` كان بيمسحهم ومايرجّعهمش.
**وده حصل فعلاً:** الجدول اتلقى فاضي والملف ده لسه بيقول إنهم موجودين.

دلوقتي `DevAccountsSeeder` بيعملهم، و`DatabaseSeeder` بينده عليه. يعني
`migrate:fresh --seed` بيرجّعهم.

لو اتمسحوا لأي سبب:

```bash
docker compose exec backend-web php artisan db:seed --class=DevAccountsSeeder
```

الـ seeder مكتفي بنفسه — بيعمل الأدوار الأول، فالأمر ده شغال لوحده من غير
`--seed` كامل.

## بيانات تجريبية

`php artisan db:seed` بيملا القاعدة كلها: ٣ أقسام، ٥ تصنيفات بالعربي
والإنجليزي، ٦ عملاء (واحد منهم موقوف)، ١٨ تذكرة بكل الحالات والأولويات
والقنوات، ٣٩ رسالة فيهم ٣ ملاحظات داخلية، مرفقين على الديسك فعلاً، وحسابين
بورتال.

بيشتغل تاني من غير ما يكرر حاجة — كل سيدر بيدوّر بمفتاح طبيعي قبل ما يكتب.
و`./scripts/restart.sh` بينده عليه في كل المسارات، وبيوقف بـ `SEED_FAILED`
لو فشل.

التذاكر كلها بتتعمل من خلال أوامر مديول Tickets، مش `insert` مباشر — يعني
ليها `ticket_events` و `version` وتواريخ صح. تفاصيل السبب في
`DemoTicketsSeeder`.

لو عايز الحسابات بس من غير الداتا التجريبية:

```bash
php artisan db:seed --class=DevAccountsSeeder
```

### ليه باسورد معروف مكتوب في ملف

`DevAccountsSeeder` **بيرفض يشتغل خارج `local` و `testing`**. مفيش بيئة
الباسورد ده بيفتح فيها حاجة. لو الحارس ده اتشال، الباسورد لازم يتشال معاه.

## لو الدخول رجّع 500 بدل ما يشتغل

`Session store not set on request.` معناها إن الطلب مجاش من نطاق مسجّل في
`SANCTUM_STATEFUL_DOMAINS`. المتصفح على `localhost:3000` مظبوط. لو بتجرّب
بـ `curl` لازم تبعت:

```
-H 'Origin: http://localhost:3000'
```

من غيرها Sanctum مابيشغّلش وضع الجلسة أصلاً.

## ملاحظة عن المتصفح

صفحة `/sign-in` عندك بيملاها Chrome أوتوماتيك بـ `admin@pharmacy.local` وباسورد
محفوظ — **دي بيانات مشروع تاني** ومش هتشتغل. امسحها من الحقول قبل ما تكتب
البيانات الصح.

## مهم: كونتينرات دوكر بتشتغل بصورة مبنية، مش بسورس مربوط

`frontend` و `backend-web` الاتنين `build:` من غير volume للسورس. يعني اللي
شغال في دوكر هو الكود وقت آخر `docker compose build` — مش اللي على الديسك.

اتلقى ده يوم 2026-09-03: الكونتينرات كانت شغالة من ٢٨ ساعة، و`/portal/sign-in`
كان بيرجّع 404 وهو موجود على الديسك وكل تستاته خضرا.

**قبل ما تجرب أي حاجة جديدة في المتصفح:**

```bash
docker compose build frontend backend-web && docker compose up -d
```

أو شغّلهم من الهوست على طول:

```bash
cd frontend && pnpm dev
cd backend && php artisan serve --port=8000
```

`docker compose stop frontend backend-web` الأول عشان البورتات تفضى.

**اتبنوا من جديد يوم 2026-09-03 والاستاك دلوقتي على آخر كود** — واتأكدت بدخول
فعلي من المتصفح على البورتال. بس ده هيبقى قديم تاني بعد أي استوري جاية، فأي
تجربة في المتصفح لازم يسبقها build أو تشغيل من الهوست.
