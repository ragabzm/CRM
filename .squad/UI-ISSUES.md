# مشاكل الواجهة — جولة بصرية 2026-09-02

جولة على الستاك الشغال في Docker (`localhost:3000`)، **من غير تسجيل دخول**.
**ما اتصلحش أي كود** — الملف ده تسجيل بس.

نطاق الجولة: الصفحات المفتوحة + الصفحات اللي المفروض تكون محمية. الجزء اللي
بعد تسجيل الدخول لسه ما اتشافش (محتاج حد يسجّل الدخول — شوف `DEV-CREDENTIALS.md`).

## 🔴 عالي — صفحات محمية بتفتح من غير تسجيل دخول

**الأعراض:** كل الصفحات دي فتحت بالكامل والمتصفح **مش مسجّل دخول**. مفيش تحويل
لـ `/sign-in`، ومفيش `ForbiddenState`.

| المسار | اللي حصل |
|---|---|
| `/` | الصفحة الرئيسية اتعرضت كاملة بالشل |
| `/customers` | الجدول والفلاتر وزرار "Add customer" كلهم ظاهرين |
| `/profile` | الفورم كامل ظاهر (بحقول فاضية) |
| `/admin/audit-log` | **شاشة الأدمن** اتعرضت كاملة بالفلاتر والجدول |

`/admin/audit-log` هي الأخطر: ستوري 499 بندها العاشر بيقول
> `ForbiddenState` rendered when API returns `403`

اللي بيحصل فعلاً إن الصفحة بتترسم عادي وبتعرض حالة "مفيش نتايج".

**ملاحظة:** الـ API نفسه محمي صح — بيرجع `401` مع Problem Details:
```json
{"type":"https://errors.ragab-crm/platform.unauthorized","status":401,
 "code":"platform.unauthorized","detail":"This endpoint requires an authenticated caller."}
```
المشكلة في الواجهة: بتترسم قبل ما تتأكد من الجلسة، وبتعامل الـ 401 كأنه
"مفيش بيانات".

## 🟠 متوسط — `/tickets` بيدي 404 غير منسّقة جوه الشل

**المسار:** `/tickets` (من الشريط الجانبي مباشرة)

صفحة 404 الافتراضية بتاعة Next.js — **بلوك أسود** بيغطي منطقة المحتوى كلها،
مكتوب فيها `404 | This page could not be found.`، وهي **جوه** الشل بتاع
التطبيق (الشريط الجانبي والعلوي فوقها).

مفيش `app/not-found.tsx` في المشروع، فالمستخدم بيشوف صفحة خطأ لا شكلها ولا
لغتها من التطبيق (إنجليزي ثابت، مش من `messages/`).

السبب الجذري: `Sidebar.tsx` سطر 23 بيحط وجهة `/tickets` بينما `app/tickets/`
مش موجود أصلاً. متوقَّع — stories التذاكر (503→507) لسه ما خلصتش — بس النتيجة
إن رابط في التنقّل الأساسي بيكسر.

## 🟡 منخفض — طلب API غير مصادَق ومش JSON بيرجّع 500

**إعادة الإنتاج:**
```bash
curl -i http://localhost:8000/api/v1/customers          # → 500
curl -i -H "Accept: application/json" \
        http://localhost:8000/api/v1/customers          # → 401 صح
```

**من لوج الكونتينر:**
```
{"message":"Route [login] not defined.",
 "context":{"exception":{"class":"Symfony\\Component\\Routing\\Exception\\RouteNotFoundException",
 "file":"/app/vendor/laravel/framework/src/Illuminate/Routing/UrlGenerator.php:542"}},
 "level_name":"ERROR","module":"Customers"}
```

لما الطلب مايطلبش JSON، Laravel بيحاول يحوّل لراوت اسمه `login` — وهو مش
مسجّل — فبيرمي استثناء وبيطلع 500 بدل 401.

ستوري 492 بندها التامن بيقول:
> Every non-2xx response is `application/problem+json`

الرد ده مش كده.

## البند 1 — التفصيل المهم

الملف بيقول "الواجهة بتترسم قبل ما تتأكد من الجلسة". دي مش القصة الكاملة.

**مفيش أي حماية للمسارات أصلاً.** مفيش `middleware.ts`، ومفيش فحص جلسة على
السيرفر في أي `layout` أو `page`. `/` و `/profile` مابيعملوش أي طلب ممكن
يولّد تحويل من أساسه.

**والآلية الاحتياطية الوحيدة مفصولة.** `SessionExpiryListener` بيستنى حدث
اسمه `auth:session-expired` — و**محدش في المشروع كله بيطلق الحدث ده**.
`lib/api/request.ts` بيتعامل مع 409 بشكل خاص ومفيهوش فرع لـ 401 خالص. وكمان
الثابت في الفرونت `security.session_expired` بينما الباك إند بيرجّع
`platform.unauthorized` — يعني حتى لو اتوصّل، الكود مش هيطابق.

**ستوري 496 بندها متعلّم `[x]` وبيقول العكس:**
> - [x] Session expiry returns `401 session-expired`; frontend redirects to `/sign-in?redirect=…`

التست بيعدّي لأنه **بيطلق الحدث بنفسه** (`window.dispatchEvent` جوه التست).
يعني بيختبر المستمع، وعمره ما اختبر الناشر — والنص الناقص هو بالظبط النص
اللي مفيش تست عليه.

**تصحيح للخطورة:** مفيش أي بيانات بتتسرّب. الـ API محمي صح وبيرجّع 401،
فاللي بيتعرض شل فاضي. دي مشكلة ثقة وتجربة استخدام — مش تسريب بيانات.
`/admin/audit-log` ما عرضش ولا إدخال واحد.

**جزء منها مجدول:** ستوري 507 سطر 250 بتخطّط لتحويل 401 مركزي في
`request.ts`. بس دي الستوري رقم ١٦ من ٢٢ — والبوابة مالهاش تستنى كده،
خصوصاً إن 496 مدّعية إنها خلصتها.

## البند 1 — الطرفين

**الناشر اللي كان ناقص.** `lib/api/request.ts` بقى بيطلق
`auth:session-expired` على أي 401 — ما عدا `security.invalid_credentials`،
عشان باسورد غلط مش جلسة منتهية. وكوّدات الانتهاء بقت اتنين
(`platform.unauthorized` من T0 و `security.session_expired` من Security)
بدل واحد ماكانش بيتبعت أصلاً.

**والبوابة على السيرفر.** `lib/auth/session.ts` + `middleware.ts` +
`app/(app)/layout.tsx`. المسارات المحمية اتنقلت لمجموعة واحدة
`app/(app)/`، والبوابة بتشتغل قبل أي رسم.

`__tests__/api/session-expiry.test.ts` **مابيطلقش الحدث بنفسه** — بيسمع بس.
دي الفرق بينه وبين `SessionExpiryListener.test.tsx` اللي كان بيعدّي وهو
بيختبر نص الآلية.

## البند 2 — ليه حصل

`AppShell` كانت في الـ root layout، واللي بيلف كمان مسارات `(auth)`. يعني
شاشة تسجيل الدخول كانت بتعرض شريط جانبي مليان وجهات مقفولة — وده بالظبط
اللي `(auth)/layout.tsx` مكتوب فيه إنه مش عايزه. وعشان الشاشات ماكانتش
تعرف هي جوه شل ولا لأ، اتنين منها لفّوا نفسهم كمان.

`__tests__/architecture/app-shell-single-mount.test.ts` بيقع لو رجع تركيب تاني.
